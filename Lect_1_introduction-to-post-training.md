## 2. What Is Post-training?

### The training pipeline

| Stage | Starting point | Data learned from | Result |
|---|---|---|---|
| **Pre-training** | Randomly initialized model | Knowledge "from everywhere": Wikipedia, Common Crawl (crawled internet data), GitHub (coding data) | **Base model**: predicts the next word/token (a token is a sub-word) |
| **Post-training** | Base model | **Curated data**: chat data, tool-using data, agent data | **Instruct / chat model**: responds to instructions and talks to the user |
| **Further post-training** | Instruct model | Data that changes behavior or enhances certain capabilities | **Customized model**: specialized in certain domains or with specific behaviors |

### Examples from the lecture
- **Instruct model:** Asked "What is the capital of France?", it answers that the capital of France is Paris.
- **Customized model:** May write better SQL queries for given instructions.

### Key idea
- Pre-training = learning knowledge broadly.
- Post-training = learning *responses* from curated data, then optionally continuing to change behavior or enhance specific capabilities.

## 3. Methods Used During LLM Training

### 3.1 Pre-training (for reference)

- Considered **unsupervised learning**.
- Starts from a very large-scale **unlabeled text corpus** (Wikipedia, Common Crawl, GitHub, etc.).
- Can extract **more than 2 trillion tokens** from this corpus and train on all of them.
- **Objective:** minimize the **negative log probability of each token conditioned on all previous tokens**.
- **Minimal example:** the sentence *"I like cats"*
  1. Minimize negative log probability for **"I"**
  2. Then for **"like"** given "I"
  3. Then for **"cats"** given "I like"
- Result: the model learns to **predict the next token given all previous tokens seen**.

---

### 3.2 Supervised Fine-Tuning (SFT)

- One of the **simplest and most popular** post-training methods.
- Considered **supervised learning** or **imitation learning**.
- **Dataset:** labeled **prompt-response pairs**
  - **Prompt** = usually the instructions to the model
  - **Response** = the ideal response the model should give
- **Data scale:** only about **1,000 to 1 billion tokens**. This is much less than pre-training.
- **Biggest difference in the training loss:** the model is trained **only on the tokens of the response, not the tokens of the prompt**.

---

### 3.3 Direct Preference Optimization (DPO)

- A more advanced post-training method.
- **Dataset format:** a **prompt** plus a **good response** and a **bad response**.
  - For a given prompt, generate multiple responses, then select one considered **good** and one considered **bad**.
- **Training goal:** push the model **away from the bad responses** and have it **learn from the good responses**.
- **Data scale:** also about **1,000 to 1 billion tokens**.
- Uses a **more sophisticated loss function** (covered in a specific later lesson).

---

### 3.4 Online Reinforcement Learning (Online RL)

- **What you prepare:** only **prompts** and a **reward function**.
- **Process:**
  1. Start from a prompt.
  2. Ask the **language model itself** to generate a response.
  3. Compute a **reward** for that response using the reward function.
  4. Use that signal to **update the model**.
- **Data scale:** about **1,000 to maybe 10 million or more prompts**.
- **Objective:** **maximize the reward** for the prompt and response, where the response is **generated by the language model itself**.

---

### 3.5 Comparison of Post-training Methods

| Method | Data you need | Approximate scale | Core learning signal |
|---|---|---|---|
| **SFT** | Labeled prompt-response pairs | 1,000 to 1 billion tokens | Imitate the ideal response (loss on response tokens only) |
| **DPO** | Prompt + good response + bad response | 1,000 to 1 billion tokens | Move toward good, away from bad responses |
| **Online RL** | Prompt + reward function | 1,000 to 10 million+ prompts | Maximize reward on the model's own generated responses |

## 4. Three Elements for Successful Post-training

### Element 1: Good co-design of data and algorithm
- There are different post-training choices: **SFT**, **DPO**, and different online RL algorithms such as **REINFORCE / RLOO, GRPO, or PPO**.
- Each requires a **slightly different data structure** to prepare.
- A good **co-design of data and algorithm** is really important for success.

### Element 2: A reliable and efficient library
- Needs to implement most algorithms **correctly**.
- **Hugging Face TRL**
  - One of the first libraries that is **simple to use**.
  - Implements most of the algorithms mentioned.
  - **Used for most coding practices throughout this course.**
- More sophisticated and **memory-efficient** libraries recommended to try:
  - **OpenRLHF**
  - **veRL**
  - **NeMo RL**

### Element 3: An appropriate evaluation suite
- You need to understand what evaluations are needed **before and after** post-training.
- Used to **track model performance** and ensure the model keeps performing well.

### Important caveat
- It is **easy to improve any single benchmark**.
- It is **much harder** to improve a benchmark or **change certain model behavior without degrading other domains**.
- Throughout the course, the aim is to explore **which method gives the best improvement without degrading other domains**.

## 6. When Should You Do Post-training?

Post-training is **not necessarily needed in every use case**. Other approaches may be more appropriate depending on the scenario.

| Scenario | More appropriate approach | Reasoning from the lecture |
|---|---|---|
| Model only needs to follow **a few instructions** (e.g., "do not discuss something sensitive," "do not compare your company with another company") | **Prompting** | Easy to do, but **simple yet brittle**: in edge cases the model may not always follow all the instructions |
| Need to **query a real-time database or knowledge base** | **Retrieval-Augmented Generation (RAG)** or search-based methods | Can **adapt to a rapidly changing knowledge base** |
| Need a **domain-specific model** (e.g., medical or cybersecurity LLM) | **Continual pre-training, followed by standard post-training** | Model first **learns the knowledge**, then **learns how to talk to the user** |
| Need to follow **20 or more instructions tightly**, or **improve target capabilities** (e.g., strong SQL model, function-calling model, reasoning model) | **Post-training** | Can **reliably change model behavior** and **improve targeted capabilities** |

### Details on continual pre-training
- Injects **very large-scale domain knowledge** that was **not seen in the pre-training dataset**.
- Ideally the domain knowledge should be **more than 1 billion tokens**.

### Warning on post-training
- If post-training is **not done correctly**, it might **degrade other capabilities** that you did not train on.

## 7. Key Takeaways (Summary)

1. **Pipeline:** random init, then **pre-training** (base model, next-token prediction), then **post-training** (instruct/chat model), then **further post-training** (customized model).
2. **Pre-training** is unsupervised: trained on 2+ trillion tokens, minimizing negative log probability of each token given previous tokens.
3. **SFT:** supervised/imitation learning on prompt-response pairs (1K to 1B tokens); loss on **response tokens only**.
4. **DPO:** learns from a prompt with good vs. bad responses (1K to 1B tokens); more sophisticated loss.
5. **Online RL:** needs prompts and a reward function (1K to 10M+ prompts); the model generates its own responses and is updated to **maximize reward**. Algorithms mentioned: REINFORCE/RLOO, GRPO, PPO.
6. **Three keys to success:** (a) data-algorithm co-design, (b) a reliable, efficient library (Hugging Face TRL in this course; also OpenRLHF, veRL, NeMo RL), (c) an appropriate evaluation suite.
7. **Evaluation caution:** improving one benchmark is easy; improving it without degrading other domains is hard.
8. **Choose the right tool:** prompting (few, simple instructions), RAG (real-time knowledge), continual pre-training + post-training (domain-specific models, 1B+ tokens), post-training (tight adherence to 20+ instructions or targeted capability gains).
9. **Risk:** poorly done post-training can degrade capabilities you didn't train on.
