# Lecture Notes — Basics of SFT


---

## 1. Lecture Overview

This lesson covers:

- The basic concepts of **supervised fine-tuning (SFT)**, including the method
- Common **use cases** for SFT
- Principles for **high-quality data curation** in SFT
- The difference between **full fine-tuning** and **parameter-efficient fine-tuning**

---

## 2. What Is SFT?

- SFT can be considered as **imitating example responses**.
- You can start from **any language model** that can predict a response given a prompt.
- The starting point can be a **base model**.
  - When a user asks a question, a base model might just predict the most likely next token.
  - As a result, it may continue with a very similar question **instead of answering** the question.

### Preparing labeled data

- To perform SFT on a base model, you need **labeled data** in the format of **user questions and ideal assistant responses**.
- Examples from the lecture:
  - User: *"Tell me about your identity."* → Assistant: *"I'm Llama"* (or whichever model you want it to be).
  - User: *"How are you?"* → Assistant: *"I'm doing great."*
- By preparing a **large dataset** of such labeled data, you are ready to do SFT and imitate the example responses in the data.

### Result of SFT

- After SFT on a base model, you get a **fine-tuned model** or **instruct model**.
- If done correctly, it can **respond to any user query properly**.

---

## 3. The SFT Loss Function

### Core idea

- SFT works by **minimizing the negative log likelihood** of the response given the prompt, summed over all labeled data.
- Minimizing the negative log likelihood is **equivalent to maximum likelihood** and is the **cross-entropy loss**.

### Formula breakdown

- For any data point with index *i* (a specific **prompt–response pair**):
  - The SFT loss = the **negative of the log probability of the response given the prompt**.
- This can be further written as the **negative log likelihood**, where:
  - The **likelihood is a product** of the probabilities of each **token in the response**,
  - Each conditioned on **all prior tokens, including the prompt tokens**.

### Why SFT is imitation

- The model is trained to **maximize the probability of outputting the provided response given the prompt**.
- That is why SFT is described as trying to **imitate the example responses**.

---

## 4. Best Use Cases for SFT

### Use case 1: Jump-starting a new model behavior

Examples:

- Turning a **pre-trained language model into an instruct model**.
- Turning a **non-reasoning model into a reasoning model**.
- Getting a model to **use certain tools without tool descriptions in the prompt**.
  - The model simply assumes it already has access to the tools and **calls them in its responses**.

SFT is described as **ideal** for jump-starting such behaviors.

### Use case 2: Improving certain model capabilities

- A highlighted scenario is **distillation**: distilling capabilities into a **smaller model** by training on **high-quality synthetic data generated by a larger model**.
- In effect, you distill a larger model's capability into a small model using supervised fine-tuning.

---

## 5. Principles for High-Quality SFT Data Curation

### Common methods

| Method | How it works |
|---|---|
| **Distillation** | Generate responses from a **stronger, larger instruct model**; a **smaller model imitates** those generated responses. |
| **Best-of-K / Rejection sampling** | Generate **multiple responses from the same original model** you want to train; select the **best** using a **reward function or other automatic method**; then imitate those best responses generated by the model itself. |
| **Filtering** | Start from a **very large-scale SFT dataset** (e.g., from **HuggingFace** or an **internal database**); filter by **quality of responses** and **diversity of prompts** to get a **smaller dataset** that is higher quality and diverse enough. |

### Key principle: quality over quantity

- In SFT data curation, **quality is much more important than quantity** for improving capabilities.
- Example from the lecture: **1,000 really high-quality and diverse examples** can usually **outperform the SFT results of 1 million mixed-quality examples**.

### Rationale

- SFT requires **imitating all the data you provide**.
- If the mixed-quality data contains **really bad responses**, the model is **forced to imitate** them, which **degrades performance**.
- Therefore, **data quality is critical** for the success of SFT.

## 6. Full Fine-Tuning vs. Parameter-Efficient Fine-Tuning (PEFT)

- This is an **orthogonal direction** in model tuning — completely **parallel to any post-training method**.

### Setup (for a single neural network layer)

- **h** = the layer's output
- **W** = the original weights of the layer
- **x** = the layer's input

### Full fine-tuning

- Add a **ΔW** (delta W) to the original weights, where ΔW comes from **gradient descent**.
- ΔW has the **exact same size as the original weights**.
- This requires introducing an **additional d × d parameters** for the model updates.

### Parameter-efficient fine-tuning

- Keep the original output **h**, input **x**, and original weights **W**.
- Instead of adding a ΔW of the same size as W, add the **product of two smaller matrices, B · A**:
  - **B** is a **d × r** matrix
  - **A** is an **r × d** matrix
  - **r is usually much smaller than d**
- The **effective number of parameters to update** is only the total parameters in **B and A**, which can be **much smaller than the original weights**.
- Benefits: **saves a lot of memory** and makes computation **more efficient**.

### Combining with training methods

- Both full fine-tuning and parameter-efficient fine-tuning can be **used in combination with any of the training methods** discussed in the course:
  - **Supervised fine-tuning**
  - **Direct preference optimization**
  - **Online reinforcement learning**
- It is **your choice** whether to use full or parameter-efficient fine-tuning with any of these methods.

### Trade-off (e.g., LoRA)

- PEFT methods like **LoRA** save a lot of memory.
- However, they also **learn less and forget less**, because there are **fewer parameters to tune**.

---

## 7. Key Takeaways

1. **SFT = imitating example responses** by training on labeled prompt–response pairs.
2. A base model may continue the prompt rather than answer it; SFT yields an **instruct model** that responds properly.
3. The loss is the **negative log likelihood** (cross-entropy) of the response given the prompt, using token probabilities conditioned on all prior tokens including the prompt.
4. Best use cases: **jump-starting new behaviors** (instruct, reasoning, tool use without tool descriptions) and **improving capabilities** (e.g., distillation to a smaller model).
5. Data curation methods: **distillation, best-of-K / rejection sampling, filtering**.
6. **Quality beats quantity**: 1,000 high-quality, diverse examples can outperform 1 million mixed-quality ones, because bad responses get imitated too.
7. **Full fine-tuning vs. PEFT** is independent of the training method; PEFT (e.g., LoRA) updates **B·A** with a small rank **r**, saving memory but learning less and forgetting less.
