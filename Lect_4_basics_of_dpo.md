# Lecture Notes: Basics of DPO

## 1. Lecture Overview

This lesson covers the basic concepts of Direct Preference Optimization (DPO), including:

- The method itself
- Common use cases
- Principles for high-quality data curation in DPO

---

## 2. What DPO Is

- DPO can be considered a **contrastive learning method** that learns from both **positive and negative responses**.
- Like SFT, you can start from **any LLM**, but it is usually recommended to start from an **instruct LLM**, i.e. a model that can already answer some basic questions from the user.

---

## 3. Running Example: Changing Model Identity

### Starting point
- User asks: *"Who are you?"* → Assistant says: *"I'm Llama."*
- Goal: change the model's identity.

### Step-by-step workflow
1. **Curate comparison data** prepared by a labeler.
   - The labeler can be a **human labeler** or a **model-based labeler**.
2. For a prompt such as *"Tell me your identity"*, prepare **at least two responses** (required for DPO to work):
   - **"I'm Athene"** → labeled the **preferred (positive)** response
   - **"I'm Llama"** → labeled the **less preferred (negative)** response
3. This encourages the model to say "I'm Athene" over "I'm Llama" when answering identity-related questions.
4. Perform DPO on top of the language model using the prepared comparison data, with the DPO loss function.
5. The result is a **fine-tuned LLM** that learns from both positive and negative samples and tries to **imitate the preferred samples**.
6. When the user later asks "Who are you?", the assistant should hopefully answer **"I'm Athene"** rather than "I'm Llama".

---

## 4. The DPO Loss Function

### 4.1 High-level view
- DPO minimizes a **contrastive loss** that **penalizes the negative response** and **encourages the positive response**.
- The DPO loss is a **cross-entropy loss on the reward difference** of a **re-parameterized reward model**.

### 4.2 Structure of the loss
- The loss is the **negative log of a sigmoid function** of a log difference.
  - σ (sigma) = the sigmoid function
  - **β (beta)** = a very important **hyperparameter** that can be tuned during DPO training
    - The **higher β is, the more important the log difference** becomes.
- Inside the parentheses there are **two log-ratio terms**: one for the **positive sample** and one for the **negative sample**.

### 4.3 The log-ratio terms
Each term is a **log of the ratio of two probabilities**:

| Component | Meaning |
|---|---|
| **Numerator: π_θ** | The **fine-tuned model** (θ = the weights being tuned). Gives the probability of the response given the prompt. |
| **Denominator: π_ref** | The **reference model**: a **copy of the original model with fixed weights** (**not tunable**). Gives the probability the original model assigns to generating that response given the prompt. |

- The **positive-sample term** uses the probability of the **positive response** given the prompt.
- The **negative-sample term** uses the same log-ratio structure for the **negative response**.

### 4.4 Interpretation as a reward model
- Each log-ratio term can be viewed as a **re-parameterization of a reward model**.
- Under that view, the DPO loss is a **sigmoid function of the reward difference** between the positive and negative samples.
- Essentially, DPO tries to:
  - **Maximize the reward** for the positive sample
  - **Minimize the reward** for the negative sample
- For details on why the log ratio can be viewed as a re-parameterization of a reward model, the lecture recommends reading the **original DPO paper**.

## 5. Best Use Cases for DPO

### Use case 1: Changing model behavior (most important)
- DPO is really good when you want to make **small modifications of model responses**.
- Examples:
  - Changing the **model identity**
  - Improving **multilingual responses**
  - Improving **instruction-following capability**
  - Changing **safety-related responses**

### Use case 2: Improving model capabilities
- When done right, DPO can be **better than SFT** at improving model capabilities.
- Reason: its **contrastive nature**, since it sees **both good and bad samples**.
- It can be even better for improving capabilities when DPO is done **on-policy** (as described in the data curation section below).

---

## 6. Principles of Data Curation for DPO

### Method 1: Correction method
- **Generate responses from the original model** and treat each as a **negative sample**.
- **Enhance/modify** the response to turn it into a **positive response**.
- Example (identity change):
  - Negative (generated by the current model): *"I'm Llama"* for the question "Who are you?"
  - Edit the response directly: replace "Llama" with the desired identity, giving **"I'm Athene"** for the same question → this becomes the **positive** response.
- Benefit: you can **automatically create large-scale, high-quality contrastive data** for DPO training.

### Method 2: Online / on-policy DPO (special case)
- Generate **both positive and negative examples from the model's own distribution**.
- Process:
  1. Generate **multiple responses** from the current model (the one you want to tune) for the **same prompt**.
  2. Collect the **best response as the positive** sample and the **worst response as the negative** sample.
- To decide which response is better or worse, use a **reward function** or **human judgment**.

---

## 7. Pitfall: Avoiding Overfitting in DPO

- DPO is essentially doing **reward learning**, so it can **easily overfit to shortcuts**.
- Preferred answers may contain **shortcuts** that make them easy to distinguish from non-preferred answers.
- Example: if the **positive samples always contain a few special words** while the **negative samples do not**, training on such a dataset can be **very fragile**.
- Such data may require **much more hyperparameter tuning** to get DPO working.

---

## 8. Key Takeaways (Quick Review)

1. DPO is a **contrastive learning** method using **positive and negative** responses; start from an **instruct LLM**.
2. You need **at least two responses per prompt** (one preferred, one less preferred), labeled by a **human or model-based labeler**.
3. The loss is **−log σ(β · [log-ratio of positive − log-ratio of negative])**, where each log ratio compares the **fine-tuned model π_θ** to a **fixed reference model π_ref**.
4. The log ratios act as a **re-parameterized reward model**, so DPO **maximizes the positive reward and minimizes the negative reward**.
5. **β** is an important hyperparameter: a **higher β** makes the log difference **more important**.
6. Best for **changing model behavior** (identity, multilingual, instruction following, safety) and can **improve capabilities** better than SFT when done right.
7. Data curation methods: **correction method** and **online/on-policy** best-vs-worst selection (via reward function or human judgment).
8. Watch out for **shortcuts** in the data that cause **overfitting** and fragile training.
