# Lecture notes — Basics of Online RL

---

## 1. Lecture Overview

This lecture covers:
- Basic concepts of online reinforcement learning (RL)
- The method itself and common use cases
- Principles for high-quality data curation in RL
- A comparison of two online RL algorithms: **PPO** (Proximal Policy Optimization) and **GRPO** (Group Relative Policy Optimization)

---

## 2. Online vs. Offline Learning in RL for Language Models

| Aspect | Online Learning | Offline Learning |
|---|---|---|
| Data source | Model generates new responses in real time | Pre-collected prompt–response–reward tuples |
| Process | Iteratively collects new responses and their rewards, then uses them to update weights | No fresh responses generated during learning |
| Loop | Updated model produces new responses as it keeps learning and updating itself | Learns purely from the fixed dataset |

- **Online RL** = RL methods applied in the online learning setting.

---

## 3. How Online RL Works (Overview)

The model **explores better responses by itself**. Workflow:

1. Start with a **batch of prompts**.
2. Send prompts to an existing **language model**, which generates corresponding responses.
3. Send the (prompt, response) pairs to a **reward function**, which labels a reward for each pair.
4. This yields tuples of **(prompt, response, reward)**.
5. Use these tuples to **update the language model**.

- The update step can use different algorithms. This lecture covers two: **PPO** and **GRPO**.

---

## 4. Choices of Reward Function

### 4.1 Option 1: Trained Reward Model

**How the data is built**
- Multiple responses are generated by the model or collected from different sources.
- A human judges them and states a preference for one response over another.

**How the reward model is trained**
- A reward model is trained on this data to compute a reward for each response (summary).
- Loss = **log of the sigmoid of the difference between the two rewards**.
- When a human labeler says response *j* is better than response *k*, the loss is designed to:
  - encourage a **higher reward for response j**
  - discourage a higher reward for response k
- Result: more preferred responses consistently receive higher rewards than less preferred ones.

**Characteristics**
- Usually **initialized from an existing Instruct model**.
- Trained on very large-scale human- or machine-generated preference data.
- Works for **any open-ended generation**.
- Great for improving **chat capabilities** and **safety-related domains**.
- Can be **less accurate for correctness-based domains**, such as:
  - hard coding questions
  - math questions
  - function-calling use cases

### 4.2 Option 2: Verifiable Rewards

Designed for **correctness-based domains**.

**Math**
- Check whether the response's exact answer **matches the ground truth** (given the assumptions that exist).

**Coding**
- Verify correctness by **running unit tests**.
- Provide a large number of unit tests as **test input + ideal test output** pairs.
- Run the code and check whether the execution result matches the provided test output.

**Preparation effort required**
- Ground truth for math datasets
- Unit tests for coding
- A very good **sandbox execution environment** for multi-turn agent behavior

**Trade-off**
- Requires more effort in preparation, but the effort **pays off** with a **more reliable reward function**, which can be **even more precise than a reward model** in these domains.
- This approach is also **used more often for training reasoning models**, which aim to be strong at questions like coding and math.

## 6. Proximal Policy Optimization (PPO)

### 6.1 Architecture and Model Roles

**Color convention in the diagrams**
- **Yellow blocks** = trained models (weights are updatable)
- **Blue blocks** = frozen models (weights are not updated)

**Pipeline**
1. Start with a set of queries **q**.
2. Send to the **policy model** (the language model itself, which is being updated/trained).
3. The policy model generates output/responses **o**.
4. The response is provided to **three** other models:

| Model | Role | Trainable? |
|---|---|---|
| **Reference model** | A copy of the original model; used to compute **KL divergence** so the language model does not change too much from its original weights | Frozen |
| **Reward model** | Takes the query and output and produces a **reward** used to update the policy model | Frozen |
| **Value model (critic model)** | Assigns value to **each individual token**, so the **response-level reward can be decomposed into token-level credit** | Trainable |

### 6.2 Advantage Estimation
- After computing the reward and the value model's output, **Generalized Advantage Estimation (GAE)** is used to estimate the **advantage (A)**.
- Advantage characterizes the **credit / contribution of each individual token** to the entire response.
- The per-token advantage is used as the signal to guide the update of the policy model.

### 6.3 PPO Objective
- PPO tries to **maximize the expected advantage** for the current policy π_θ.
- Problem: we cannot directly sample from the most recent model π_θ; we only have data from a previous step's model, **π_θ_old**.
- Solution: **importance sampling trick**
  - Take the expectation over responses generated by π_θ_old.
  - Multiply by an **importance ratio = π_θ / π_θ_old**
  - π_θ_old = language model from the previous step; π_θ = language model at the current step.
  - This lets us effectively maximize expected advantage for the current policy π_θ.
- **Clipping:** extra tricks keep the ratio from becoming too large or too small during training.
  - The loss takes the **minimum** of:
    1. the direct ratio × advantage
    2. the clipped ratio × advantage
- **Summary:** PPO is an **importance-sampling-based method** that maximizes advantage for the current policy π_θ.

## 7. Group Relative Policy Optimization (GRPO)

### 7.1 Similarity to PPO
- GRPO also uses **advantage** and maximizes **the exact same objective formula** to update the language model.

### 7.2 Key Difference: How Advantage Is Computed
**Pipeline**
1. Start from a query **q**, send it to the policy model.
2. The policy model generates **multiple responses as a group** (O1 … OG).
3. The **reference model** and **reward model** still compute the KL divergence and the reward for each response.
4. This yields a group of outputs and rewards for the same query.
5. A **group computation** calculates the **relative reward** for each output.
6. The **relative reward is taken as the advantage for each individual token** in that output.
7. This advantage is used to update the policy model.

- This gives a **more brute-force estimation of advantage** for each token.

---

## 8. PPO vs. GRPO — Core Differences

After advantage is obtained, PPO and GRPO are very similar. The main difference lies in **how advantage is estimated**.

| Feature | PPO | GRPO |
|---|---|---|
| Value (critic) model | **Uses** an actual value model that must be trained throughout | **Removes** the value model |
| Memory | More GPU memory (due to value model) | **More memory efficient** |
| Advantage granularity | **Different advantage for each token** — shows which tokens matter more or less | **Same advantage for every token** within the same output |
| Feedback type | **Fine-grained**, token-level | **Uniform** across tokens in a response |
| Advantage estimation | Via value model + GAE | **More brute-force**, from group-relative rewards |

**Summary**
- **PPO:** a value/critic model assigns credit to each token, so each word/token in a generation gets a different advantage value.
- **GRPO:** without the critic model, all tokens in the same output share the same advantage.

---

## 9. Use Cases: When to Use Which

Both PPO and GRPO are very effective online RL algorithms.

### GRPO
- Design is **better suited for binary or correctness-based rewards**.
- Because it only assigns credit to **full responses** rather than individual tokens, it **requires a larger number of samples**.
- Requires **less memory** since no value model is needed.

### PPO
- Usually works well with **both reward models and binary rewards**.
- Can be **more sample efficient** when it has a **well-trained value function**.
- May require **more GPU memory** because of the actual value model.

---

## 10. Key Takeaways

1. **Online RL** has the model generate fresh responses, get rewards, and update itself iteratively; **offline** learning uses only a fixed pre-collected dataset.
2. The online RL loop: **prompts → language model → responses → reward function → (prompt, response, reward) tuples → model update**.
3. Two reward function options:
   - **Trained reward model** — trained with a log-sigmoid loss on reward differences from human preference data; best for open-ended generation, chat, and safety; less accurate for correctness-based domains.
   - **Verifiable reward** — ground-truth matching for math, unit tests for coding, sandbox environments for multi-turn agents; more effort but more reliable and precise; commonly used for reasoning models.
4. **PPO** uses a policy model, reference model, reward model, and a trainable **value/critic model**, with GAE for token-level advantage, importance sampling, and ratio clipping.
5. **GRPO** samples a group of responses per query, uses **group-relative rewards** as the advantage, and **drops the value model**.
6. Trade-offs:
   - **PPO:** fine-grained token-level credit, potentially more sample efficient, but more GPU memory.
   - **GRPO:** memory efficient and well suited for binary/correctness rewards, but uniform per-response credit and needs more samples.
